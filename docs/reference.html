§0

What Vitalstead does

A local MCP server that connects your wearable account (WHOOP today), pulls your sleep, recovery, cycle and workout data, and writes it as plain CSV files on your own machine. Nothing is uploaded anywhere except the provider's own API. No sync happens unless you (or Claude, on your request) explicitly ask for one.

connect_providerOAuth

Connects a new wearable account. Opens a browser for WHOOP login, exchanges the authorization code for tokens, and stores them in the macOS Keychain — never in a config file, never in this conversation.

Data access

list_dataRead

Lists every discovered source, its CSV files, and the date range each one covers.

Known limitation — status always reads "connected" — there's no live token check yet. A silently expired connection only surfaces once you actually run a sync.
query_dataRead

Asks a question about your synced data without opening the CSV yourself. Aggregates only by default — raw rows never enter the conversation unless you ask.

ParamTypeRequiredNotes

Provisional values — a row whose score_state is PENDING_SCORE (e.g. today's not-yet-closed cycle) is still counted in the aggregate, but flagged via provisional_count/provisional_note in the response — its value (like today's strain) updates live until WHOOP finalizes it.

Walkthrough

From a blank install to your first query, step by step.

  1. Install & configure
    Install the .mcpb extension. Claude Desktop prompts for a data folder and, optionally, your WHOOP Client ID / Secret right away — or leave them blank and fill them in later via the extension's own configure screen.
  2. Register a WHOOP developer app
    Set the redirect URI to exactly http://127.0.0.1:53682/callback, request scopes offline, read:sleep, read:recovery, read:cycles, read:workout.
  3. Connect
    Ask Claude to connect WHOOP. A browser opens for you to log in and approve access — the callback comes straight back to the local server, nothing routes through the model.
  4. First sync
    Backfills 365 days automatically. You'll get back record counts per data type and the exact date range — not the values.
  5. Ask questions
    "What's my average recovery this month?" runs through query_data — aggregate only, unless you ask for raw rows.
  6. Keep it current
    Run sync_now whenever you want fresh data — it's incremental after the first backfill, so it stays fast.
§4

Behind the scenes

Things that happen automatically, worth knowing about.

Token refresh

WHOOP access tokens live 1 hour. Every sync refreshes proactively at the start, and again mid-sync if a long backfill runs past that window — no manual re-login needed.

Concurrent syncs on the same connection dedupe the refresh call: it happens exactly once, not once per parallel request.

Where credentials live

The macOS Keychain — ~/Library/Keychains/login.keychain-db — under a service name scoped per connection, e.g. vitalstead.whoop.conn_ab12…. Never in a config file, never logged.

If reconnection is needed

Should WHOOP revoke or expire the refresh token, the next sync returns a structured error with recovery: "Reconnect the data source." — not a silent failure.

What never enters the conversation

Passwords, tokens, and full API response bodies — by design. Health values only appear if you explicitly set include_raw: true, or paste your own CSV.

Live vs. finalized values

Sleep, recovery, cycle and workout scores aren't all final the moment they exist — WHOOP marks each row's score_state, and a still-open period (typically today's not-yet-closed cycle) sits at PENDING_SCORE while its strain keeps updating live through the day.

query_data doesn't hide these rows, but does flag them (provisional_count) — a resync later may show a different number for the same row, and that's expected, not a bug.

§5

Errors & recovery

Every failure comes back structured — a kind, a plain-language message, and a recovery Claude relays verbatim instead of guessing.

{
  "status": "error",
  "error": {
    "kind": "refresh.client_error",
    "message": "The provider rejected the authentication refresh request (HTTP 401).",
    "recovery": "Reconnect the data source."
  }
}
no_data_folder_configured
Set a data folder before syncing. Fix: call set_data_folder first.
missing_client_credentials
WHOOP Client ID/Secret aren't set yet. Fix: enter them in the extension's configure screen.
invalid_days
The days override was outside 1–3650. Fix: pick a value in range, or omit it entirely.
sync.fetch_failed
The provider's response couldn't be read after retries. Fix: retry the sync; report it if it persists.
refresh.client_error
The refresh token was rejected — usually expired or revoked. Fix: reconnect via connect_provider.
Vitalstead is local-first: CSV files live only in the folder you choose, sync only happens when you ask, and disconnecting a provider never deletes data you already have.
