# EPIC-05 — Garmin: ручной ZIP-импорт (post-MVP, D-018)

Перенесён в post-MVP решением D-018 — закрытый MVP ограничен одним работающим
провайдером (WHOOP, EPIC-04). Критерии приёмки ниже сохранены без изменений,
переоткрываются при возврате к задаче.

Garmin Connect Developer Program заморожен (родительский T-002), OAuth-подключение
невозможно. Режим MVP — ручной экспорт из Garmin Connect → ZIP → импорт (D-005
соблюдается: никаких логинов/паролей Garmin, в т.ч. неофициальных библиотек).

## T-501 [P1] Разбор ZIP-экспорта Garmin

Критерии приёмки:

- из официального ZIP-экспорта Garmin извлекаются sleep, stress, body battery, HRV,
  activities → 5 CSV по унаследованному CSV-контракту;
- upsert по стабильному ID записи (D-009): повторный импорт того же/пересекающегося
  экспорта не создаёт дубликатов;
- битые/неожиданные файлы внутри архива пропускаются с перечислением в отчёте,
  не валят импорт целиком;
- FIT-файлы в MVP пропускаются с пометкой в отчёте (разбор FIT — T-502);
- тесты на синтетическом мини-архиве (анонимизированном).

## T-502 [P2] Разбор FIT-файлов

Критерии приёмки:

- активности из FIT (crate `fitparser` или эквивалент) дополняют activities CSV
  полями, отсутствующими в JSON/CSV-части экспорта;
- решение о добавляемых колонках проведено через правила эволюции схемы
  унаследованного CSV-контракта.

## T-503 [P1] Tool import_garmin_zip

Критерии приёмки:

- tool принимает путь к ZIP, валидирует существование/читаемость до начала работы;
- ответ — отчёт: сколько записей по каждому типу создано/обновлено/пропущено,
  без значений health-данных (D-015);
- импорт атомарен по контракту синка: сбой на середине не оставляет частично
  перезаписанных CSV.
