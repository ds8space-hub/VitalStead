## What this product is

**Vitalstead** — форм-фактор продукта Control Your Data в виде **Claude plugin +
локальный MCP-сервер**: skill + slash-команды + локальный MCP-коннектор, который
по OAuth забирает wearable-данные (Oura, WHOOP; Garmin — ручной ZIP-импорт) и
пишет их в CSV в выбранную пользователем папку. Health-данные не покидают
машину пользователя, кроме явных запросов через tools (по умолчанию — только
агрегаты, D-015). Родительский Tauri-проект остаётся post-validation треком под
именем Control Your Data; ядро у обоих общее. Решение о переименовании этого
форм-фактора в Vitalstead: D-020 в `docs/decisions.md`.

## Key architectural decisions to respect

Унаследованы все D-001…D-013 родительского проекта (см. таблицу в `docs/decisions.md`);
критичные для кода:

- **Local-first (D-001)**: CSV живут только в папке пользователя; remote MCP-connector запрещён.
- **CSV, не база (D-002)**; **upsert по стабильному external_id (D-009)**.
- **Sync только по требованию (D-003)**: tool call — и есть «по требованию».
- **Никогда не собирать пароли провайдеров (D-005)**.
- **Отключение не удаляет CSV (D-010)**.
- **Ядро платформонезависимо (D-011)**: `core/` без `#[cfg(target_os)]`; платформенные
  реализации только в `platform/`, собираются в composition root (`lib.rs`).
- **D-014**: форм-фактор — plugin + локальный MCP; целевая платформа MVP — Claude Desktop.
- **D-015 (жёсткое правило)**: секреты никогда не попадают в контекст модели. Tools не
  возвращают токены/secrets; OAuth-обмен целиком внутри сервера; health-данные в модель —
  только по явному запросу, по умолчанию агрегаты.
- **D-016**: закрытый MVP распространяется через personal marketplace; публичная
  директория — post-MVP.

## Sync atomicity contract

Синк провайдера успешен только когда: все запланированные страницы API получены, ответы
преобразованы и провалидированы, все затронутые CSV записаны без ошибок, новые файлы
заменили старые атомарно, новый sync cursor персистирован. Сетевая ошибка никогда не
переводит источник в `disconnected`; ранее синхронизированные CSV остаются доступными.

## Security rules (non-negotiable)

Никогда не логировать: Authorization headers, access/refresh tokens, client secrets,
authorization codes, полные OAuth callback URL, полные API-ответы с health-данными.
Никогда не коммитить: client secrets, токены, экспорты health-данных, реальные ответы
API провайдеров — фикстуры только анонимизированные.

## Workflow: 3 роли на каждую T-задачу

Кодовые T-задачи ведутся трёхролевым циклом (см. `docs/dev-orchestration.md`):
Оркестратор (`solution-architect`, Sonnet) пишет spec по контрактам → Разработчик
(`backend-developer`, Haiku) реализует quote-then-code с тестами → Тестировщик
(`qa-engineer`, Sonnet) прогоняет Gate 1 + security-чек-лист. Максимум 3 цикла
на задачу, дальше — эскалация пользователю. Документационные задачи цикла не требуют.

## Working discipline

- Задача не считается завершённой без зелёного `cargo test`.
- Никогда не `Edit`/`Write` файл, не прочитанный в текущей сессии; не гадать пути — искать.
- Не перезапускать упавшую команду без диагностики; не перегонять тесты без изменения кода.
- Новое продуктовое решение → нумерованная запись в `docs/decisions.md` + каскад во все
  затронутые доки в том же изменении.
- Решения родительского проекта не редактируются отсюда; конфликт с ними → новая запись
  D-0xx здесь с пометкой, что она уточняет/замещает родительскую.
